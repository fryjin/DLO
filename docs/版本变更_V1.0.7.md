# Dopamine Cloud Lite V1.0.7 — 他人数据空间浏览与刷新位置修复

## 本轮修复

### 1. 他人数据空间可切换套餐

- 在只读数据空间开放 `packageSelect`，与已有 `projectSelect` 一样作为纯浏览操作。
- 切换套餐会更新当前视图内的产品、费用、折扣及利润计算展示，但不会标记为待保存，更不会向他人账号发送保存请求。
- 产品、套餐、费用等增删改操作仍禁止；「保存」和「数据管理」在他人空间继续隐藏。

### 2. 浏览器刷新后保留上次查看的数据空间

- 每名登录账号分别保存上次查看的账号空间：`dopamine-cloud-last-view-owner-<当前登录账号>`（浏览器本地 localStorage）。
- 只有在成功读取并切换到目标空间后才记录偏好，避免失败时被记录为错误选项。
- 刷新页面后通过原有登录会话从 Worker 再次获取该空间的最新数据，而不是强制切换到本人空间。
- 同时沿用已存在的独立浏览偏好，恢复查看的项目和各项目下的套餐选择。
- 如果上次空间暂时无法读取，则尝试安全回退至本人空间。
- 用户确认执行「同步到我的数据」后会回到本人空间，并将本人空间记为当前查看位置。
- 明确执行「退出登录」时会清除上次查看的账号空间偏好；下一次登录默认进入本人空间。

## 数据与权限

- 没有新增、修改或删除 D1 表和字段，不需要执行数据库迁移。
- 没有修改 Worker API、账号密钥、业务定价算法或自动保存周期。
- 浏览偏好仅存在当前浏览器，不写入任何账号的业务 JSON，也不构成跨设备同步。
- 原有账号权限与 JSON 导入导出规则保持不变。

## 验证

- `npm run check`：JavaScript 检查、5 项 Worker 服务端测试、构建通过。
- `python tests/browser_dom_smoke.py`：原有账号权限、只读限制、覆盖同步、退出确认通过。
- `python tests/view_space_reload_regression.py`：切换他人空间、只读套餐/项目切换、重新初始化页面后恢复查看空间与所选套餐、只读不触发 POST、不同登录账号偏好隔离均通过。
- 当前浏览器自动化运行环境禁止真实网址跳转，所以刷新回归采用**相同浏览器环境重新初始化页面 DOM 与应用脚本，保留本地存储**的模拟方式；尚未在实际 Cloudflare 线上执行 F5 验收。

## 部署

解压完整项目包后，覆盖 `fryjin/DLO` 仓库 `main` 分支对应文件；Cloudflare Worker Builds 完成后使用 Ctrl+F5 刷新。

**不需要执行 D1 SQL、不需要修改 Cloudflare 绑定及任何登录 Secret，也不影响独立 V8 本地版。**
