# V1.0.2：先迁移 D1，再升级 GitHub

适用现有：`fryjin/DLO` → `dopamine-cloud-lite` Worker → `dopamine-cloud-lite` D1。无需新建仓库、Worker、数据库或密钥。

## 一、升级前备份（重要）

1. 继续使用 **V1.0.1** 的网页，由任一账号登录，打开「数据管理 → 导出备份」，安全保存当前共享数据的 JSON。
2. 如果其他账号还有尚未保存的改动，先沟通保存和刷新；最终 D1 的 `shared_document` 快照是迁移源。
3. **先执行下面的 D1 SQL，再上传新版 GitHub 文件**，避免自动部署新代码后表尚不存在导致读取失败。

## 二、D1 Console 建表和复制三份数据

Cloudflare → Storage & Databases → D1 → `dopamine-cloud-lite` → Console。

打开 ZIP 中：`docs/sql/V1.0.2_D1_Console_初始化.sql`。

将**两条 SQL 完整复制到 Console 执行**。该文件开头没有 `--` 注释，避免 Console 把后续语句视为注释。

创建的是一个 D1 表：

```sql
CREATE TABLE IF NOT EXISTS account_documents (
  user_id TEXT PRIMARY KEY REFERENCES users(id) ON DELETE CASCADE,
  data_json TEXT,
  version INTEGER NOT NULL DEFAULT 0,
  updated_at INTEGER,
  updated_by TEXT
);
```

然后以 `INSERT OR IGNORE ... SELECT ...` 把原共享数据复制给三个现有账号。**不会删除或更改旧 `shared_document` 表，也不会覆盖已创建的个人行。**

执行结束后，另外复制执行 `docs/sql/V1.0.2_D1_Console_核验.sql` 中的查询：

```sql
SELECT u.username, d.version, d.updated_at,
       LENGTH(d.data_json) AS json_length
FROM account_documents AS d JOIN users AS u ON u.id=d.user_id
ORDER BY u.username;
```

预期返回 `admin01 / admin02 / admin03` 三行；初次迁移三行 `json_length` 相同且非空（若此前共享空间未保存过项目，长度可能为空，此时每人首次打开会各自创建默认项目，需要手动保存）。

**核验三行之后，再继续下一步。**

提示：仓库内还提供 `migrations/0002_account_documents.sql`，供以后采用 Wrangler 的标准迁移方式；本次通过网页 D1 Console 手工执行时，请勿在已经手工迁移后再重复使用 Wrangler 的历史初始化流程，防止重复操作。该迁移本身已通过 `IF NOT EXISTS` / `INSERT OR IGNORE` 设计为幂等。

## 三、上传完整 V1.0.2 ZIP 代码

1. 解压 `Dopamine_Cloud_Lite_V1.0.2_三账号独立数据空间版.zip`。
2. 打开 GitHub：`https://github.com/fryjin/DLO`，将代码覆盖同名文件并提交到 `main`。**保留 `wrangler.jsonc` 中原有 D1 database_id**（该 ZIP 已基于原 V1.0.1）。
3. 等待 Cloudflare Workers Builds：`npm run build` + `npx wrangler deploy` 成功。
4. 刷新 `https://dopamine-cloud-lite.frychengeng.workers.dev/`；原登录密钥和 Worker `KEY_PEPPER` 不变。

不要上传 `.private`、登录密钥或业务备份到公开 GitHub。

## 四、逐项验收

1. 登录炮台：查看自己的产品，再选择「芋头」：顶部出现「只读」，商品字段、编辑和保存按钮被禁用，可以浏览项目/套餐。
2. 切回炮台，新增「炮台测试产品」，保存。芋头本人登录时看不到这个新增产品；芋头切到炮台的只读视图时可以看到。
3. 选择芋头数据，点击「同步到我的数据」→「取消」，检查炮台自己数据未变化。
4. 再次点击「同步到我的数据」→「确认覆盖并同步」，检查炮台自己的全部项目现在与芋头当前**已保存**的内容一致，而芋头本人内容没有变化。
5. 在炮台数据再改一个价格并保存，查看芋头本人数据仍不变。
6. 保留五分钟自动保存与刷新测试；关闭带未保存修改的标签仍只弹浏览器原生提示，不静默保存。
7. 各账号分别导出 JSON，可以在本地 V8.0.4 中恢复。

## 回滚方案

如果发现异常：先保留当前 D1 数据及 JSON 备份；把 Worker 代码回退 V1.0.1。V1.0.1 仍读取旧 `shared_document`，但**V1.0.2 的每个账号独立数据不会自动合并回旧共享表**。不能把代码回滚理解为个人数据自动回滚；如需恢复请基于导出的 JSON 谨慎处理。
