# Dopamine Cloud Lite V1.0.2 — 三账号独立数据空间

## 已实现

1. **三个账号的数据隔离**：同一个 D1 数据表 `account_documents`，每个账号对应独立一行 JSON 数据，继续保留完整 V8 定价/组合计算和高精度计算。
2. **只有本人可写**：Worker 根据登录会话确定数据库 `user_id`，普通保存只能更新自己的行；带 `owner` 指向别人的写入请求被拒绝。不是只靠前端禁用按钮。
3. **查看他人数据（只读）**：工作台顶部选择炮台 / 芋头 / EE 的数据空间，可以查看对方的项目、产品、组合、套餐和定价；产品修改、添加、删除、导入及保存控件被禁用。只读时仍可切换项目/套餐、搜索、展开组合、导出 JSON。
4. **确认同步覆盖**：查看别人的数据时显示「同步到我的数据」，点击后弹窗明确提示目标数据将完整覆盖、无法页面内撤销。点击确认才调用 Worker 原子 SQL 将**对方已保存**的数据复制到本人名下，对方数据不变，然后返回本人的编辑模式。
5. **原有数据无损分离**：SQL 迁移先将当前 `shared_document` 快照分别复制给三个账户。保留原始共享表不删除。未来各自编辑分开保存。
6. **五分钟保存与刷新**：本人编辑时每五分钟尝试自动保存 + 刷新自己数据；浏览他人时每五分钟仅获取当前查看空间最新数据，不保存任何内容。关闭页面的原生未保存警告保留。
7. **兼容**：继续沿用炮台/芋头/EE 的原密钥，旧 Worker Secret `KEY_PEPPER` 不变；本地 V8 互通的 JSON 文件格式不变。

## 同步规则和限制

- 同步粒度为**整个账号数据空间**，包含所有项目和套餐。不是追加、合并，也不是同步某一个产品。
- 同步只复制对方**已经保存到云端**的数据，不会复制对方浏览器中尚未保存的修改。
- 必须先保存或取消自己的未保存修改才能切换空间。
- 同一个账号在多个浏览器同时编辑，仍采用 Last Write Wins；不同账号不会再因普通保存互相覆盖。
- V1.0.2 不提供历史版本撤销、实时编辑/编辑锁/操作日志；覆盖前建议导出自己的备份 JSON。
- 部署前务必**先执行 D1 数据迁移**，否则新版 Worker 会提示 `账号数据尚未初始化`，不会误写旧共享表。

## 验收重点

- 三账号初始项目相同；之后各账号修改后各自数据不同。
- 只读查看能看到更新内容，但无法修改、删除、导入或保存对方数据；测试绕过前端的跨用户 API 保存应被拒绝。
- 取消同步不改变自己或对方数据；确认后只有自己变为对方最新保存的数据。
- 从 A → B 同步之后，B 后续修改不会自动影响 A。
- JSON 导出与本地 V8.0.4 导入互通仍然正常。
