# Dopamine Cloud Lite 首次部署与验收

## 0. 先保护旧数据

1. 在原有 **Dopamine Pricing Web V8.0.4** 点击「数据管理 → 导出备份」。
2. 将 JSON 备份保存在电脑或外接盘，**不要传到公开 GitHub**。
3. 新建 GitHub 私有仓库，例如 `dopamine-cloud-lite`，不要沿用现有仓库。压缩包解压后上传全部源文件，不上传 `dist` 或 `.private`。
4. 登录 Cloudflare，创建新的 Worker / D1，不修改旧 Pages、旧 Worker 或旧域名。

## 1. 依赖及新建 D1

本地安装 Node.js 20.19+、npm 和 Wrangler。命令在项目根目录运行：

```bash
npm install
npx wrangler login
npx wrangler d1 create dopamine-cloud-lite
```

命令会输出数据库 `database_id`，编辑 `wrangler.jsonc`：

```json
"database_id": "粘贴你自己的 UUID"
```

随后执行：

```bash
npm run db:migrate:remote
```

这会执行 `migrations/0001_initial.sql`，新建三个业务表和单份共享文档。它不会导入任何本地数据。

## 2. 本机生成 3 个账号与强密钥

```bash
npm run credentials:create
```

本机生成两个文件：

- `.private/login-credentials.txt`：三位用户的账号与各自 256-bit 随机密钥；包含 Worker 专用 `KEY_PEPPER`。
- `.private/seed-users.sql`：仅包含摘要，不含明文账号密钥。

**这两个文件不要上传 GitHub，不要发给我，也不要放到公开网盘。**

首次部署设置服务端密钥：

```bash
npx wrangler secret put KEY_PEPPER
```

按提示粘贴 `.private/login-credentials.txt` 中的 `KEY_PEPPER`。

导入三个账号的摘要：

```bash
npx wrangler d1 execute dopamine-cloud-lite --remote --file=.private/seed-users.sql
```

将各自账号的密钥通过安全方式交给使用者；不要把密钥写入前端 JavaScript 或仓库 Secrets 以外的环境变量。

## 3. 生产发布

```bash
npm run deploy
```

Wrangler 会同时部署 `dist` 静态文件与 `src/worker.js`。无须创建第二个 Pages 项目。发布成功后可通过 Cloudflare 分配的 `https://<worker-name>.<your-subdomain>.workers.dev/` 打开页面。

需要 GitHub 自动部署时，可在 Cloudflare 连接新 GitHub 仓库到独立 Workers Builds 流程，构建 `npm run build`，部署 `npx wrangler deploy`。初次发布推荐手动操作，确认 Secret 和 D1 都已生效后再接自动化。

## 4. 初次验收（真实 Worker 环境必做）

- 错误账号或密钥无法登录；正确三个账号均可登录。
- 账号 A 新建产品、修改单品标价并保存；账号 B 登录/等待刷新，可以看到 A 的修改。
- B 修改后保存，A 等待同步后可以看到 B 的修改。
- 修改组合成份成本/售价，组合与套餐折扣、利润自动联动；验证高精度。
- 当前存在未保存修改时，点击「退出登录」三选项可正常工作。
- 当前存在未保存修改时直接关闭标签，浏览器显示**原生离开确认**；不会云端自动提交。
- 本地版导出 V8 JSON → Cloud 导入 → 保存 → 云端登出重新登录数据仍在。
- Cloud JSON 导出 → 本地版恢复 → 数字、组合、套餐内容相同。
- Windows Chrome、Edge 及中国大陆真实网络实测。

## 5. 备份与恢复

每周至少从 Cloud 导出一次 JSON 并离线保存。当前一份共享文档采用 Last Write Wins，不支持在 Cloud 一键恢复覆盖前状态。Cloudflare D1 的 Time Travel 在 Free 计划具有有限时间窗口，恢复前需关注 Cloudflare 官方规则；应用自身不做不可变版本日志。

## 6. 限制与关闭页面说明

浏览器的 `beforeunload` 事件不能弹出自定义内容，也不能在关闭标签时可靠等待 Worker POST 返回，因此**不承诺“关闭标签 → 自定义三选一 → 保存完成才关闭”**。此项目采用：

- 应用内「退出登录」：可等待「保存并退出」成功。
- 浏览器直接关闭/刷新：只有原生「离开/取消」提示，不提交数据。
- 平时有修改每 5 分钟自动保存。重新打开后从 D1 获取最新数据。

**注意：** 中国大陆访问 Workers 免费域名可能不稳定，无法通过换数据库来解决前端网络不可达。
