# Dopamine Cloud Lite V1.0.8

三账号独立业务数据空间 · 可互相只读查看 · 确认后复制覆盖自己的数据。

## V1.0.3 变更

- 移除顶部「同步最新」「取消修改」，手动「保存」仍保留。
- 顶部「当前账号 / 退出登录」移至左侧导航最底部的圆形头像菜单。头像显示「炮」「芋」「EE」，点击可查看登录身份并退出。
- 小于等于 1200px 的窄屏侧栏会隐藏，账号头像会固定在页面左下角，确保仍可退出。
- 保留账号独立存储、查看他人、覆盖同步确认、自动保存、自动读取最新版本及退出前未保存提示。
- 本轮只修改前端，不修改 D1 表结构、Worker API、现有账号密钥。**无需执行新的数据库迁移 SQL。**


**与旧版 Dopamine Pricing Web V8 本地版独立共存，不影响其 localStorage 数据。**

## 账号与权限

- 炮台 → `admin01`
- 芋头 → `admin02`
- EE → `admin03`

登录密钥仍使用 V1.0.1 的三组密钥，不修改 Worker `KEY_PEPPER`、不重新导入 users 或 sessions。

每个账号只能修改自己的业务数据。Worker 服务端的 `/api/state` 写入只绑定登录身份，不允许指定其他 `owner`；跨账号只读 GET 可以用 `/api/state?owner=admin02`。同步用 `POST /api/state/sync` 并传 `{ "source": "admin02" }`，只更新当前登录账号。数据库只有一个 `account_documents` 表，每个账号对应独立一行。

- `docs/sql/V1.0.2_D1_Console_核验.sql`

详细步骤：[`docs/V1.0.2_升级部署与验收.md`](docs/V1.0.2_升级部署与验收.md)。

## 主要功能

- 沿用 V8.0.4 产品、组合、套餐、附加费用、折扣利润及 BigInt 高精度算法。
- 每个人维护自己的产品和项目，不会因另一个账号保存而覆盖。
- 顶部「数据空间」可以切换为其他账号；他人数据只能只读查看、浏览，不能保存或导入/导出 JSON。
- 查看他人时「同步到我的数据」需要危险操作确认，**覆盖整个自己的数据空间**，而不是按产品追加或合并。复制对方已保存的数据，源账号不受影响。
- 本人仍然每 5 分钟自动保存改动并刷新；只读查看他人时每 5 分钟只刷新、不保存。
- 关闭标签仅在未保存时显示浏览器原生提醒，不发送静默保存请求。
- JSON 导入/导出兼容本地 V8.0.4（手动文件传输，不是双向实时同步）。

## 设计和限制

- 旧 `shared_document` 仍完整保留，可作为迁移前历史快照；数据迁移一开始为三人分别克隆该快照。
- 一账号跨设备同时编辑仍按 Last Write Wins，无编辑锁、无历史版本回退。
- 同步到自己会丢弃自己当前保存的所有项目内容，建议先导出个人 JSON 备份。
- 共享源数据为空时不能执行覆盖同步。
- 需要真实 Cloudflare 部署后验收；`workers.dev` 在中国大陆的网络可达性不能保证。

查看具体更新：[`docs/版本变更_V1.0.2.md`](docs/版本变更_V1.0.2.md)。


## V1.0.4 — 吸顶表头穿透修复

- 修复外层页面滚动时，产品信息表头以及套餐折扣表头穿透到上方操作区的显示问题。
- 表格保持独立横向、纵向滚动；容器内的列标题继续吸顶。
- 只修改表格裁切与层级相关 CSS，不变更产品/组合/套餐计算、账号权限、同步或自动保存。
- 不涉及数据库结构修改，直接覆盖 GitHub DLO 后构建部署；无需执行 SQL 或重新配置 Secret。


## V1.0.5 — 彻底修复响应式吸顶间隙

V1.0.4 虽然为表格增加了绘制范围限制，但在屏幕宽度 ≤1600px 的样式中，
`--subhead-h` 被定义在 `.page-head` **元素自身**，而相邻兄弟元素 `.toolbar` 无法继承，
仍使用根元素的 98px。于是标题栏实际高度 88px/78px，工具栏吸顶偏移却多出 10px/20px，
表格表头在这段空隙中露出；在浏览器缩放或窄导航模式下尤其明显。

此版把两档高度写在全局 `:root`（≤1600px 用 88px，≤1200px 用 78px），
同时标题栏和工具栏从同一变量取值；保留之前的表格裁切和内部 sticky 表头。

- 复现并修复「套餐售价计算」中的 `6折/6.5折/7折` 输入框从工具栏上方露出。
- 修复「产品信息设置」同类表头穿透。
- 提供 `tests/sticky_offsets_regression.py`，覆盖 1817、1454（1.25 DPR 模拟缩放）、1024、900px；
  同时验证两页面外层吸顶区域**无缝衔接**，以及表格内纵向滚动和表头吸顶。
- 仅修改 `v8.css` 布局变量、页面显示版本号和版本文档。账户、D1、Worker API、密钥均不变。
- **升级方式：** 覆盖 `fryjin/DLO` 的 `main`，等待 Worker Builds 构建后按 `Ctrl + F5`。
  不需要再次执行 SQL 或生成密钥。


## V1.0.6 — 仅允许本人数据空间保存与备份

- 切换到他人数据空间时，隐藏整个顶部「数据管理」菜单与「保存」按钮；「同步到我的数据」仍可用，且必须确认后才覆盖自己的数据。
- 本人数据空间继续显示「数据管理」「保存」，可导出/恢复自己的 JSON；返回本人空间恢复显示。
- 客户端操作函数增加权限边界校验（尤其防止读取备份文件时中途切换空间）。
- 保留 5 分钟自动保存本人修改、读取当前空间最新数据；他人空间只读取，不保存。
- Worker 已有的 POST `/api/state` 写入账号隔离保持不变；数据表、账号密钥与 D1 均不改动，无需执行 SQL。

## V1.0.7 — 只读套餐浏览与查看位置记忆

- 查看其他账号时，现在可以自由切换其**项目及套餐**，不允许修改数据，也不会保存到对方的 D1 记录。
- 刷新页面会恢复上次正在查看的账号数据空间，并在可能时恢复对应项目与套餐；各登录账号的浏览偏好独立存储于当前浏览器。
- 同步覆盖到本人空间之后恢复本人视图；主动退出登录后，下次登录默认打开本人空间。
- 维持原有保存、备份权限及五分钟刷新和自动保存机制。
- 详情与测试记录：[`docs/版本变更_V1.0.7.md`](docs/版本变更_V1.0.7.md)。无 D1 迁移。


## V1.0.8 — 手动 / 自动保存时间与黄灰绿配色

- 顶部状态统一使用「**手动保存 15:20**」「**自动保存 15:20**」；仅在相应的 Worker 保存请求成功时更新，时间使用用户浏览器当地时间。
- 每 5 分钟检测云端，有本地未保存修改时才向 D1 写入，**没有修改时只读取、不虚报保存成功，也不重复覆盖云端**。
- 页面刷新后，云端已存在的历史记录显示「上次保存 HH:MM」（旧记录无法可靠判断当时是手动还是自动）。
- 其他设备修改了本人账号的数据并刷新到当前页面，则显示「云端更新 HH:MM」；跨账号主动同步完成则显示「同步完成 HH:MM」。
- 原来 ≤950px 会隐藏保存状态，本版调整为窄屏依旧显示。修改未提交显示「有未保存的修改」，失败显示「云端保存失败」。
- 全站重配色：**暖灰背景 + 鼠尾草绿主操作和利润 + 柔和芥末黄折扣及次级重点**，登录页、工作台、导航、表格及弹窗统一；危险操作/错误仍用红色。
- **本版不更改** D1 数据表、账号、Worker API、权限及保存间隔。已从 V1.0.7 升级的站点只需覆盖上传 GitHub DLO/main，等待 Worker 自动构建部署，不必运行迁移 SQL。
- 具体修改与测试：[`docs/版本变更_V1.0.8.md`](docs/版本变更_V1.0.8.md)。
